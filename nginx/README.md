# Nginx reverse proxy (chat stack)

The tracked configuration is [`nginx.conf.template`](nginx.conf.template).
`nginx/nginx.conf` is generated by `scripts/render_nginx_conf.sh` and must not
be committed (see root `.gitignore`). The template has no deployment-time
envsubst variables, so rendering is a plain copy.

## Render `nginx.conf`

```bash
./scripts/render_nginx_conf.sh
```

Docker example:

```bash
./scripts/render_nginx_conf.sh
docker run --rm -p 8080:8080 --add-host=host.docker.internal:host-gateway \
  -v "$(pwd)/nginx/nginx.conf:/etc/nginx/nginx.conf:ro" nginx:alpine
```

## Routing layout

The template defines **two upstream blocks**, each with one `server`:

- `nbhx_backend` — FastAPI application on `host.docker.internal:8000`.
- `nbhx_vite` — Vite dev server on `host.docker.internal:8888`.

All known `/api/v1/*` business routes are explicitly proxied to FastAPI,
including:

- `location ^~ /api/v1/chat-messages` — reserved LangChain SSE chat endpoint (buffering disabled, long read timeout).
- `location ^~ /api/v1/conversations` — reserved LangChain conversation list/rename/delete endpoints.
- `location ^~ /api/v1/messages` — reserved LangChain message list endpoint.
- `location ^~ /api/v1/context-compression/` — context compression.
- `location ^~ /api/v1/chat-summary/` — chat summary/archive.
- WebSocket prefixes `/api/v1/document-tasks/ws/` and legacy `/api/v1/docs/ws/`.
- Backend utility endpoints `/api/v1/health`, `/api/v1/metrics` and the API
  docs (`/api/v1/docs`, `/api/v1/openapi.json`, `/api/v1/redoc`).

Unknown `/api/v1/*` paths return **404** directly. There is no catch-all
fallback to an external chat service and no deployment-time Authorization key
injection.

Until the LangChain orchestrator is implemented, the six reserved chat routes
return `501` with error code `CHAT_ORCHESTRATOR_NOT_CONFIGURED`. They still
require `Authorization: Bearer <JWT>`, so Nginx must keep the incoming
`Authorization` header unchanged (the template does no header rewriting).

## Load balancing vs path routing

The default template defines one `server` per upstream. Nginx does **not**
distribute load across multiple replicas until you add multiple `server` lines
inside the same `upstream`.

Example: two FastAPI instances behind one upstream (round-robin by default):

```nginx
upstream nbhx_backend {
    server 10.0.0.1:8000 max_fails=3 fail_timeout=30s;
    server 10.0.0.2:8000 max_fails=3 fail_timeout=30s;
    keepalive 64;
}
```

Notes for multi-instance setups:

- **WebSockets** (`/api/v1/document-tasks/ws/`; legacy `/api/v1/docs/ws/`):
  sticky routing may be required if the app assumes a fixed backend; consider
  `ip_hash` or `hash $cookie_... consistent;` on the upstream, or ensure the
  app is stateless with respect to which worker handles the socket.
- **SSE** (`/api/v1/chat-messages`): keep `proxy_buffering off` and
  `X-Accel-Buffering: no` for every backend instance.
- **Health**: open-source Nginx uses `max_fails` / `fail_timeout` on `server`;
  active health checks need a module or an external load balancer.
- **Vite**: scale it the same way by adding more `server` entries to
  `nbhx_vite`, or terminate TLS on a cloud LB and point Nginx at internal
  addresses.

## Edge hardening (optional)

The template includes:

- **Commented `set_real_ip_from` / `real_ip_header`**: uncomment and set CIDRs
  when Nginx runs **behind** another trusted proxy so `X-Forwarded-For` and
  `$remote_addr` reflect the real client correctly.
- Standard forwarding headers (`Host`, `X-Real-IP`, `X-Forwarded-For`,
  `X-Forwarded-Proto`, `X-Forwarded-Host`, `X-Forwarded-Port`).
- Unknown `/api/v1/*` returns 404 instead of proxying to an external service.

TLS termination is not defined here; use your cloud load balancer, `certbot`,
or another layer in front of this Nginx. If TLS terminates upstream, pass
`X-Forwarded-Proto: https` and enable the real-IP block as appropriate.

## Smoke test

With Nginx listening on `8080` and FastAPI reachable:

```bash
./scripts/nginx_smoke.sh
# Optional: also assert the reserved 501 payload
SMOKE_AUTH_TOKEN='<jwt>' ./scripts/nginx_smoke.sh
```

The smoke script verifies that `/api/v1/docs`, backend routes and the reserved
chat routes are reachable, that chat routes require login, and (when a token is
provided) that the reserved chat payload contains
`CHAT_ORCHESTRATOR_NOT_CONFIGURED`.
